# Private Operator Reports & Interpretation Guide

> **Creator:** `MADE BY TANVEER`  
> **Implementation:** `src/reports/generator.js`, `src/reports/notifier.js`

## 1. Report Structure

Every completed observation generates a deterministic structured JSON report and Markdown document titled:

```text
TANVEER KA BETA NEWKER — SECURITY OBSERVATION REPORT
```

Sections included in every report:
1. **Observation Metadata:** Observation ID, Server Name, Guild ID, Target Bot Name, Target Bot ID (only when verified; otherwise explicitly `UNVERIFIED (<state>)`), Start & Completion UTC timestamps, Overall Status, and Integration Status.
2. **Scenario Execution Summary:** Selected, Passed, Failed, Partial, Blocked, Inconclusive, and Cancelled counts.
3. **Detection & Performance Metrics:** All 13 metrics with exact denominators, sample sizes, and explicit `UNAVAILABLE (<reason>)` notices when telemetry is missing.
4. **Evidence Source Breakdown:** Record counts separated across the 5 canonical `EVIDENCE_SOURCES`.
5. **Evidence-Backed Findings:** Separated into `CONFIRMED_DEFECT`, `SUSPECTED_WEAKNESS`, and `INFORMATIONAL_OBSERVATION`, each citing persisted `evd_...` Evidence IDs.
6. **Critical Limitations:** Missing permissions, target ambiguity, collector warnings, or absent external telemetry.
7. **Recommended Fixes:** Actionable remediation steps paired with verification procedures and rerun scenario IDs.
8. **Controlled Test Approval Eligibility:** Assessment state (`READY_FOR_APPROVAL` vs `NOT_ELIGIBLE`), exact description of what an approved controlled simulation will do, or exact safeguard blocks.

---

## 2. Deterministic Regeneration Without Rerunning Scenarios

`ReportGenerator.generateFromDatabase(observationId)` reconstructs the complete report exclusively from persisted SQLite tables (`observation_runs`, `scenario_executions`, `findings`, `evidence_records`, `cleanup_records`). Running `/observe-report`, `/report`, or `/observe-export` produces byte-identical output without re-executing any scenario.

---

## 3. Private Delivery, Failure Notices, and DM Fallback

1. **Restricted Local Persistence First:** Written to SQLite `reports` table and `REPORT_ARCHIVE_DIR` (`./data/exports/<observationId>.md` and `.json`) with `0600` file permissions.
2. **Operator DM Delivery:** Sent exclusively to `AUTHORIZED_OPERATOR_ID` (`1131248987173814336`) via `RateLimitAwareExecutor`, split cleanly across newline boundaries (`<= 1900` chars per Discord message).
3. **DM Delivery Fallback:** If Discord cannot deliver the DM (e.g., error `50007` DMs disabled or offline mode), `OperatorNotifier`:
   - Preserves the full report in SQLite and restricted local storage (`dm_delivery_status = 'FAILED'`).
   - Sends a private ephemeral notice (`MessageFlags.Ephemeral`) on the operator's command interaction instructing them to view via `/observe-report` or `/observe-export`.
   - **Never** posts sensitive security findings into shared guild channels.
4. **Workflow Failure DM:** If an unexpected exception aborts `/observe` mid-flight, `handleFailedRun()` delivers `TANVEER KA BETA NEWKER — OBSERVATION WORKFLOW FAILURE NOTICE` detailing the failed stage, error category, last successful stage, whether database/report state was saved, and the recommended recovery command.
